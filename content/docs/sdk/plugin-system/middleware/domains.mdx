Each middleware root receives a different context object. Those context models
define what a middleware can inspect or mutate.

## Task Middleware

```python
@dataclass
class TaskMiddlewareContext:
    task: BaseTask
```

Entered by `BaseTask.run()`.

The task's [per-invocation working directory](/sdk/core/task#execution-working-directories)
is created at the **innermost** point of this chain, immediately before
`_run()`. Every middleware's `before` hook has therefore already run by the time
the directory exists.

That ordering is what makes retargeting possible. A middleware may repoint
`context.task.target` in `before` — an orchestrator re-anchoring a task the
engine added mid-run, for instance, such as a `horus_map` clone or an inlined
subworkflow body — and the directory is then created under the new target. If it
were created before the chain were entered, the retarget would land too late:
the directory would exist at the old path and the executor would launch with a
`cwd` that was never created.

No built-in middleware relies on the directory existing during `before`. If
yours does, create it yourself rather than assuming.

## Bound Task Middleware

```python
@dataclass
class BoundTaskMiddlewareContext:
    task: BaseTask
    target: BaseTarget
    input_digests: InputDigests
```

Entered by the scheduler for each attempt of a task on its acquired target,
after the task is bound to it and before the completion check. It wraps the
check, the input transfers, dispatch and wait.

Unlike Task Middleware, it runs for every placed task, including tasks that end
up skipped as complete, on every target kind. Use it for work that has to land
on the target before Horus decides whether the task is complete, such as
restoring cached outputs.

- `context.target is context.task.target`. On a node that is provisioned on
  first use, the first command in `before` provisions it.
- A node lost during the attempt re-binds the task and wraps the retry again,
  so `before` runs once per node. Raise `TargetLostError` from `before` to get
  that retry instead of swallowing it.
- `input_digests` returns the input digests the completion check uses. It is
  computed on the first await and shared with the check. Pass it to
  `task.manifest_matches(manifest, input_digests)` to know whether a stored
  completion manifest still matches before downloading anything.
- `after` must not raise: its exception would replace the attempt's.

Register it under the `horus.middleware.bound_task` entry point group.

## Workflow Middleware

```python
@dataclass
class WorkflowMiddlewareContext:
    workflow: BaseWorkflow
```

Entered by `BaseWorkflow.run()`.

## Runtime Middleware

```python
@dataclass
class RuntimeMiddlewareContext:
    runtime: BaseRuntime
    task: BaseTask
```

Entered by `BaseRuntime.setup_runtime()`.

## Executor Middleware

```python
@dataclass
class ExecutorMiddlewareContext:
    executor: BaseExecutor
    task: BaseTask
```

Entered by `BaseExecutor.execute()`.

## Target Middleware

```python
@dataclass
class TargetMiddlewareContext:
    target: BaseTarget
    task: BaseTask
```

Entered by `BaseTarget.dispatch()`.

## Transfer Middleware

```python
@dataclass
class TransferMiddlewareContext:
    transfer_strategy: BaseTransferStrategy[Any, Any]
    artifact: BaseArtifact
    source: BaseTarget
    destination: BaseTarget
```

Entered by `BaseTransferStrategy.transfer()`.

## Interaction Middleware

```python
@dataclass
class InteractionMiddlewareContext:
    transport: BaseInteractionTransport
    interaction: BaseInteraction
    renderer: BaseInteractionRenderer[Any, Any]
    attempt: int
```

Entered by `BaseInteractionTransport.ask()` once per render attempt.

This context is intentionally mutable. Middleware can replace the transport,
interaction, or renderer before the render call happens.

## Built-in Middleware

Horus currently ships two built-in middleware implementations:

- `TaskTimeMiddleware`
- `WorkflowTimeMiddleware`

Both record elapsed wall-clock time and emit timing information on the event
bus after execution completes.
